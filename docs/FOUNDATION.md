# 档案基础增量：操作及升级

## 操作顺序

1. 管理员登录，在“账号权限”创建院团内部账号、外部接收账号，并分配岗位及授权剧目。超级管理员仅通过运维命令管理，网页不允许提升为超级管理员。
2. 新建剧目，点击“详情”编辑简介、添加首演版/复排版等制作版本，并为每版添加演员角色、工作人员岗位。新建剧目自动生成“默认版”。
3. 在“演职人员”建立姓名、专业和工作简介。人员不是登录账号，不录入证件、私人联系方式等敏感信息。
4. 新建场次，选择剧目及制作版本；详情中分别添加计划阵容与实际阵容，记录替补和变更说明。已有阵容记录时不能切换版本。
5. 上传资料后，通过详情修改元数据、上传新版本。每个版本单独保留原文件、SHA-256、上传人、时间与说明，旧文件不能通过网页覆盖或删除。
6. 列表分享默认固定当前版本；详情里的历史版本也可以单独分享。后续上传新版本、修改资料名称，不改变已有链接的文件及名称快照。

当前一个场次关联一个剧目的一个制作版本，多节目晚会、档案审批、回收站尚未实现。

## 岗位与范围

| 岗位 | 档案及阵容 | 非财务资料 | 财务资料 | 对外分享 |
| --- | --- | --- | --- | --- |
| 管理员 | 全部读写 | 全部读写下载 | 全部读写下载 | 全部 |
| 档案管理员 | 范围内读写 | 范围内读写下载 | 不可见 | 可分享范围内非财务资料 |
| 业务人员 | 范围内读写 | 范围内读取下载，仅本人资料可编辑 | 不可见 | 仅本人非财务资料 |
| 财务人员 | 范围内只读 | 范围内读取下载 | 范围内读写下载 | 不可创建 |
| 普通查看 | 范围内只读 | 范围内元数据及支持格式预览 | 不可见 | 不可创建 |
| 外部接收人 | 不可进入内部档案 | 仅指定有效链接 | 仅管理员明确分享的有效链接 | 不可创建 |

范围由“账号权限”的授权剧目确定。为兼容旧数据，内部账号还保留本人上传资料的访问范围，以及本人创建/上传资料所属剧目的目录访问；移除剧目授权不会收回这部分所有者权限。若需完全停用访问，请停用账号；若只收回编辑和分享能力，可改为普通查看。普通查看仍可能保存预览内容，预览不等于防拷贝。

人员基础目录对内部岗位可见，由管理员、档案管理员、业务人员编辑。暂不包含部门继承或单文件例外授权。

财务标记在资料归类“票房”时设置，后续改为其他类别仍保留财务保护。下载、预览、列表、搜索、历史版本、分享接口使用一致的权限范围。分享每次访问重新检查创建者是否仍有分享权限，流式传输每64KB复核；停用创建者或接收者、岗位降权、移除必要的范围授权可使链接失效。恢复权限可能使未撤销、未到期的链接重新有效，需要永久失效请撤销分享。

## 升级已有试用环境

本次包含数据库迁移。更新前备份数据库和原件目录，迁移前停止业务写入，保留与数据库对应的原件快照。

Codespaces试用环境：

```bash
git pull --ff-only
python .devcontainer/start.py
python .devcontainer/welcome.py
```

普通Docker开发环境：

```bash
git pull --ff-only
docker compose up -d --build
```

Compose迁移服务会在后端启动前执行迁移；Codespaces使用原有隔离项目，不会重置账号。请确认处于`feat/archive-foundation`分支。

- 历史场次归入所属剧目的“历史默认版”。
- 历史文件转为V1，保留原存储路径、大小、哈希、上传时间，不复制、不覆盖原件。
- 历史分享固定为V1，令牌、接收者、过期时间保持不变；新增岗位和财务保护仍会检查其有效性。
- 历史内部账号默认业务人员，外部账号保持外部接收人；管理员按实际职责补充岗位与授权范围。
- 旧文件元数据字段暂留用于迁移兼容，新接口读取独立文件版本记录。

升级后抽查一个历史剧目、文件下载以及接收人链接，再开始录入新数据。需要回退时应停写并恢复升级前数据库与原件的同一备份点；不要仅运行反向迁移或只回退代码，新写入的版本可能无法由旧代码读取。

## 验证与限制

后端测试覆盖角色范围、财务隔离、版本不可覆盖、固定分享、跨资料版本拒绝、阵容约束、账户管理、旧数据库迁移。浏览器测试覆盖新增版本、角色、人员、阵容、文件版本及账号入口。

本增量尚未完成大文件续传、视频转码、部门组织树、审批、票房结构化台账、备份自动化及NAS实机验收。上传上限仍为100MB。
