# 架构决策

采用模块化单体，API与后台任务可独立部署。前端静态文件由Nginx提供，同源代理/api到Django；Session存数据库，缓存限流使用Redis，结构化数据使用PostgreSQL。原件在NAS挂载路径，按随机UUID命名，不向前端暴露存储路径。RabbitMQ/Celery预留重任务运行能力。

上传的文件作为本次不可变记录；当前没有编辑/删除文件接口。后续引入逻辑资料/版本表后保持现有原件ID可追溯。SHA-256仅用于校验，目前不进行物理去重。

当前角色：superuser=全资料管理；staff=内部用户（自己上传的资料）；普通账号=外部接收人。staff不是最终的院团岗位权限模型。剧目和场次在内部共享，资料本身按上传人隔离。

外部分享：仅保存256位随机令牌的SHA-256摘要，绑定接收账号、单份资料、过期时间和下载权限；不使用无需登录的公开下载链接。每次访问查验数据库，每个64KB输出块复核撤销及过期。网络缓冲中已发送的数据不能追回，实际60秒撤销目标需代理与网络环境测试，当前不宣称已经完成生产验收。

接收账号由管理员交互创建，创建者自行复制分享链接；系统不发送短信、邮件。PDF/图片原件预览配nosniff与CSP sandbox；上线前还需魔数校验、扫描与独立预览隔离。

本地SQLite方便开发，PostgreSQL为目标部署数据库。数据库备份必须与原件清单/恢复点配套。Redis缓存不承担业务事实保存；异步业务进度未来写入PostgreSQL。
